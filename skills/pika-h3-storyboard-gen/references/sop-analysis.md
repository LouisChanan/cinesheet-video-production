# SOP Analysis

ใช้คู่กับ [ขั้นตอนและจุดอนุมัติ](../SKILL.md) เพื่อวิเคราะห์บรีฟ ตรวจความพร้อมก่อนส่งกราฟ และบันทึกผลจากไฟล์จริง ใช้แบบบันทึกเดิมต่อจาก storyboard ถึงตัดต่อ ระบุผู้ยืนยันและไฟล์ฉบับที่ตรวจ

## 1. บรีฟและแผนเสียง

บันทึกเป้าหมาย แพลตฟอร์ม แนวภาพ เวลา อัตราส่วนหรือขนาด fps และสิ่งที่ต้องคงตามภาพอ้างอิง แบ่งเวลารายช็อต ระบุช่วงพูด จังหวะภาพ และเสียงสำคัญ ทำชุดตรวจตาม [มาตรฐาน Storyboard และภาพอ้างอิง](storyboard-and-assets.md)

| แผนเสียง | ตรวจตอนวางแผน | ตรวจจากผลจริง |
| --- | --- | --- |
| บรรยากาศ เอฟเฟกต์ หรือดนตรีบรรเลง | วางจังหวะในพรอมป์ต์ ใช้ MiniMax H3 เป็นแหล่งหลักและตรวจทางออกเสียงในกราฟ | ฟัง H3 แยก ตรวจจังหวะและเสียงพูดหรือร้องที่อาจแทรกมา |
| บรรยายทับภาพ | ใช้เสียงจาก [ElevenLabs](elevenlabs-speech.md) เป็นแทร็กเดียวต่อเนื่องเพื่อมิกซ์หลังประกอบภาพ | ฟังภาษา ชื่อเฉพาะ บทพูด ระดับเสียงเทียบกับภาพ และเสียงซ้อน |
| เห็นปากและต้องซิงก์ | ตรวจความสามารถของกราฟตั้งแต่ storyboard ก่อนใช้เครดิต วางเวลา เตรียมเสียงช่วงที่ใช้ และตรวจ LoadAudio กับ Audio VAE ถ้าสองคนพูดพร้อมกันให้เตรียมเสียงคนละไฟล์ | เทียบการขยับปากของแต่ละคนกับเสียงต้นฉบับ แล้ววางเทคที่อนุมัติซ้อนกันตรงช่วงที่พูดพร้อมกัน |
| คลิปเงียบ | ระบุในบรีฟว่าไฟล์ปลายทางต้องเงียบ | เปิดไฟล์ปลายทางตรวจตามข้อกำหนดความเงียบ |

## 2. ไฟล์ ช่องกราฟ และแท็ก

1. ใช้กราฟที่ผู้ใช้ระบุหรือกราฟที่ยืนยันกับงาน เปิด **กราฟสำเนา** เลือกเฉพาะไฟล์ที่ช็อตต้องใช้แล้วเปิดดู ตรวจว่าอ่านได้ อยู่ใน input ของ ComfyUI และตรงฉบับอนุมัติ มองหาไฟล์ค้าง เช่น `Mira.jpg` ที่เปิดจากกราฟตัวอย่าง แล้วแทนที่หรือ bypass ช่องที่ไม่ได้ใช้ ใช้ภาพร่วมซ้ำในช็อตที่เกี่ยวข้องและสลับภาพเฉพาะช็อตตามแผน
2. สำหรับกราฟ Pika H3 Flex Ref2VA ตรวจว่าโมเดล MiniMax H3 Ref2VA ผ่าน `LoraLoaderModelOnly` ที่โหลด `pika_h3_flex_ref2va_v1_bf16.safetensors` ก่อนเข้า sampler ตรวจจำนวนช่องภาพ วิดีโอ และเสียงที่ต่อเข้า `MiniMaxH3ReferenceToVideo` และช่องที่เปิดใช้จริง ใช้สำเนา `video_pika_h3_flex_ref2va_5refs_2audio.json` ที่ต่อช่องภาพ 5 และช่องเสียงเดี่ยว 2 เมื่อช็อตต้องใช้เสียงสองไฟล์ เปิด `LoadAudio` ทั้งสองช่องและจับคู่ไฟล์ที่อนุมัติกับผู้พูดคนละช่อง จัดภาพให้เรียงติดกันจากช่องแรกเมื่อกราฟรองรับ หากช่องไม่พอหรือยังระบุลำดับจริงไม่ได้ ให้พักช็อตและระบุสิ่งที่ขาด
3. **เลขช่องกราฟกับแท็กที่ H3 รับเป็นคนละค่า** ในโหนด H3 ที่ตรวจ จะข้าม input ที่ว่างและนับไฟล์ที่ได้รับตามลำดับ แยกชุดภาพและเสียง เริ่มที่ 1 ตรวจลำดับจากกราฟ/API JSON และพฤติกรรมโหนดในเครื่องก่อนเขียนแท็ก หากกราฟมีวิดีโออ้างอิงพร้อมเสียง ให้รวมเสียงของวิดีโอตามลำดับที่โหนดรับก่อนนับแท็กของเสียงเดี่ยว
4. ในขั้น storyboard ให้ร่างบทบาทด้วยข้อความ ในขั้นตั้งค่าจึงเติมแท็กจากตารางจับคู่ ตรวจ [Positive Prompt หกหัวข้อ](h3-prompt.md) กับไฟล์ส่งจริง รวมภาพที่ใช้ ช่วงเสียง และบทบาทของแต่ละไฟล์
5. ใช้ API-format workflow ของช็อต ถ้ามีเพียงกราฟสำหรับเปิดใน ComfyUI ให้ตั้งไฟล์และ bypass บนสำเนา แล้วใช้ **File → Export Workflow (API)** ตรวจ node ที่มี `class_type` และ `inputs` ไล่การเชื่อมต่อจากพรอมป์ต์และไฟล์ไปถึง H3 ตรวจว่า `CreateVideo` รับเฉพาะภาพและส่งให้ `SaveVideo` ออกเป็น MP4 ถ้าช็อตต้องใช้เสียง H3 ให้ต่อ `VAEDecodeAudio` ไปยัง `SaveAudio` เพื่อได้ไฟล์เสียงแยกสำหรับฟังตรวจ ตั้งชื่อ API JSON และไฟล์ผลลัพธ์ให้แยกช็อต ส่งเฉพาะ object ของ node กับ `comfyui_submit_workflow` เมื่อเปลี่ยนช่องที่เปิดใช้ ให้ส่งออกและตรวจ API JSON ใหม่
6. บันทึก **เวลาตาม storyboard, ค่าที่ตั้งในกราฟ, จำนวนเฟรมที่กราฟคำนวณ, fps และขนาดจริงที่ตั้ง** แยกกัน ตรวจ stride หรือกติกาการปัดเฟรมของกราฟที่ใช้ ไม่คำนวณจากวินาทีคูณ fps อย่างเดียว ตรวจบรีฟเมื่อต้องตัดสินใจเรื่องขนาดที่ยังไม่กำหนด

ตัวอย่างจากกราฟภาพและเสียงโดยตรงที่มีช่องเว้นก่อนจัดช่องในสำเนา

## 3. ตัดสินสถานะก่อนเข้าคิว

| สถานะ | ใช้เมื่อ | ขั้นถัดไป |
| --- | --- | --- |
| รออนุมัติชุดแรก | ผู้ใช้กำลังตรวจภาพ บท หรือแผนเสียง | รอยืนยันว่าทำสื่อครบได้ |
| พักช็อต | ไฟล์สำคัญอ่านไม่ได้ ขาด ไม่ได้อนุมัติ ช่องไม่พอ แท็กตรวจไม่ได้ หรือกราฟส่งเสียงที่บรีฟกำหนดออกไม่ได้ | ระบุช็อต ไฟล์หรือทางเชื่อมที่ติด และวิธีแก้ ทำส่วนที่เดินหน้าได้ต่อ |
| พร้อมรันช็อต | พรอมป์ต์ API JSON สื่อเข้า และค่ากราฟของช็อตผ่านครบ เสียงซิงก์ปากอยู่ในไฟล์ที่ผ่านและจับคู่ LoadAudio แล้วเมื่อใช้ | ตรวจคำสั่ง Gen และการอนุมัติขั้นที่เกี่ยวข้องก่อนส่ง |
| รอคำสั่ง Gen | สื่อผลิตครบ และช็อตแรกผ่านการตรวจก่อนรัน แต่ยังรอคำสั่ง Gen | ส่งชุดสรุปที่ตรวจแล้วและรอคำสั่ง |
| เรนเดอร์แล้ว · รอตรวจ | ประวัติ ComfyUI ยืนยันผลและพบไฟล์จริง | ตรวจภาพ เวลา และเสียงตามบรีฟ |
| มีแทร็ก · รอฟัง | เปิดอ่านข้อมูลแล้วพบแทร็ก แต่ยังไม่มีผลตรวจฟัง | ส่งไฟล์ให้ผู้ใช้ฟังเมื่อฟังตรวจเองไม่ได้ และบันทึกผลที่ยืนยันได้ |
| ผ่านการตรวจ | ตรวจจากไฟล์จริงครบตามบรีฟ | ดำเนินการอนุมัติช็อตทดสอบหรือส่งไฟล์สุดท้ายตามขั้น |

รายงานความพร้อมของภาพแยกจากเสียงบรรยายที่จะเข้าในขั้นมิกซ์ หากจำเป็นต้องใช้เสียง H3 แต่กราฟหรือแทร็กใช้ไม่ได้ ให้ตรวจทางเลือกที่ยังใช้ H3 ก่อนเสนอให้ผู้ใช้ตัดสินใจเรื่องแหล่งเสียงอื่น

## 4. ตรวจช็อตทดสอบ ตัดต่อ และส่งออก

- **ภาพ** ดูความต่อเนื่อง กล้อง แอ็กชัน และสิ่งที่ต้องคง เทียบกับช่องบน Character Sheet มุมฉาก หรือฉลากที่ระบุ ตรวจภาพ ณ จุดตัดตามบรีฟ
- **เวลา** อ่านจำนวนเฟรม fps ขนาดและความยาวจากไฟล์จริง แยกจากเวลาที่วางไว้ ตัดส่วนเกินได้เมื่อดูและฟังช่วงที่จะตัดแล้ว และยืนยันว่าบทพูด แอ็กชัน เสียง และจังหวะสำคัญอยู่ครบ ถ้าส่วนเกินมีจังหวะสำคัญหรือยังตรวจไม่ได้ ให้บันทึกช่วงเวลาและแจ้งผู้ใช้ก่อนตัดส่วนนั้น
- **เสียง** ฟังแทร็ก H3 แยกก่อนมิกซ์ ใช้เฉพาะช่วงที่ไม่มีเสียงพูดหรือร้อง ตรวจว่าเอฟเฟกต์ตามบรีฟยังอยู่และตรงจังหวะ ถ้าเสียงคนทับเอฟเฟกต์สำคัญ ให้หาเอฟเฟกต์ช่วงที่ไม่มีเสียงคนจาก H3 มาวางตรงจังหวะ แล้วฟังซ้ำ เมื่อบรีฟต้องการซิงก์ปาก ให้ตรวจปากของแต่ละคนเทียบกับไฟล์พูดจริงตลอดช่วงที่พูดพร้อมกัน บันทึกแยกว่าพบแทร็ก ได้ฟังแล้ว หรือมีผู้ยืนยันไฟล์ใด
- **ไฟล์สุดท้าย** ดูและฟังตั้งแต่ต้นจนจบ ตรวจความยาว ขนาด fps จุดตัด ข้อความตามบรีฟ ความต่อเนื่องและเสียงพูดซ้อน หากตรวจไม่ได้ให้ระบุสิ่งที่รอยืนยัน หากผลรันยังไม่ชัดหรือล้มเหลว ให้ตรวจคิวและประวัติงานเดิมก่อนตัดสินใจรันซ้ำ

ตัวอย่างเทียบเวลาในกราฟตัวอย่าง ตั้ง 5.00 วินาที → ได้ 124 เฟรมที่ 24 fps → ไฟล์จริง 5.167 วินาที ถ้าช่วงท้ายไม่มีเหตุการณ์สำคัญ ให้เลือกช่วงยาว 120 เฟรมสำหรับไทม์ไลน์ 5.00 วินาที แล้วตรวจไฟล์ที่ตัดอีกครั้ง หากเพียงพบแทร็กเสียงในไฟล์ สถานะเสียงคือ **มีแทร็ก · รอฟัง**
