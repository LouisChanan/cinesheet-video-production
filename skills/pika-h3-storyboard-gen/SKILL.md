# Pika H3 Storyboard Gen

เปลี่ยนบรีฟเป็น storyboard ภาษาไทยและเตรียมวิดีโอรายช็อตด้วย ComfyUI Local กราฟ Pika H3 Flex Ref2VA ใช้โมเดล MiniMax H3 Ref2VA คู่กับ Pika H3 Flex LoRA ใช้ [SOP Analysis](references/sop-analysis.md) ตรวจบรีฟ กราฟ และไฟล์จริง พร้อมบันทึกสถานะและหลักฐานรายช็อต

## มาตรฐานหลัก

- เขียน Positive Prompt ภาษาอังกฤษหนึ่งชุดต่อช็อต ใช้ [คู่มือพรอมป์ต์ H3](references/h3-prompt.md) หากกราฟบังคับให้ส่ง Negative Prompt ให้หยุดและแจ้งข้อจำกัดก่อนส่งงาน
- ใช้ MiniMax H3 เป็นแหล่งหลักของเสียงบรรยากาศ เอฟเฟกต์ และดนตรีบรรเลงตามบรีฟ ส่งออกเสียงแยกจากภาพและใช้เฉพาะช่วงที่ฟังแล้วว่าไม่มีเสียงพูดหรือร้อง
- ใช้เสียงพูดเทคที่อนุมัติแล้วในคลิปสุดท้าย หากต้องสร้างด้วย ElevenLabs ให้สร้างหนึ่งเทคต่อบท
- ใช้ Character Sheet ใหม่ในขั้น storyboard แบบแนวนอน 16:9 สามช่องตาม [มาตรฐาน Storyboard และภาพอ้างอิง](references/storyboard-and-assets.md)
- ใช้ hard cut เป็นค่าเริ่มต้น และใช้ข้อความซ้อนภาพ ซับ title card, CTA, watermark หรือ transition effect เมื่อผู้ใช้ขอ คงข้อความบนฉากหรือบรรจุภัณฑ์ตามบรีฟ

## ขั้นตอนและจุดส่งต่อ

1. **ยืนยันบรีฟ** ใช้ข้อมูลที่มีและถามทีละข้อเฉพาะเรื่องที่มีผลต่อผลส่งมอบ สรุปเป้าหมาย แพลตฟอร์ม แนวภาพ เวลา ขนาด ภาพอ้างอิง และแผนเสียง แบ่งเวลารายช็อตเมื่อมีหลายช็อต แล้วรอผู้ใช้ยืนยัน
2. **ทำ storyboard และชุดตรวจ** เปิด [มาตรฐาน Storyboard และภาพอ้างอิง](references/storyboard-and-assets.md) และ [คู่มือพรอมป์ต์ H3](references/h3-prompt.md) ถ้าใช้กราฟใหม่หรือมีข้อกำหนดสำคัญ เช่น ซิงก์ปาก ให้ตรวจสิ่งที่กราฟรองรับก่อนสร้างภาพหรือใช้เครดิตเสียง ส่ง `storyboard.md` พร้อม Storyboard Preview และภาพที่ใช้ตรวจ กรณีขอข้อความเท่านั้นให้ส่ง `storyboard.md` พร้อมแผนภาพรายช็อต หากขอเฉพาะ storyboard ให้จบที่ชุดตรวจ เมื่อผลิตต่อให้รออนุมัติชุดตรวจ
3. **เตรียมสื่อ** ส่งชุดแรกโดยเน้นช็อตแรก ได้แก่ ภาพจำเป็น บทช่วงเปิด เสียงที่เลือกหรือไฟล์ที่อนุมัติแล้ว และแนวเสียงประกอบตามบรีฟ ใช้สถานะ **รออนุมัติชุดแรก** จนผู้ใช้ให้เตรียมสื่อครบ เติมเฉพาะสื่อที่ขาดหลังอนุมัติ ใช้ [คู่มือเสียงพูด ElevenLabs](references/elevenlabs-speech.md) เตรียมและตรวจไฟล์พูด บันทึกไฟล์ที่อนุมัติ บทบาท และช็อตที่ใช้ใน SOP
4. **ตรวจ ComfyUI ก่อน Gen** ใช้กราฟสำเนาและ API JSON ของช็อตจริง ตรวจช่องภาพ วิดีโอ และเสียงตามกราฟที่ใช้ จัดช่องภาพที่อนุมัติให้เรียงติดกันได้เมื่อกราฟอนุญาต ตรวจไฟล์ค้าง ถ้าต้องซิงก์ปากสองคนในช็อตเดียว ให้ใช้กราฟที่ต่อ `LoadAudio` สองช่องและจับคู่เสียงคนละไฟล์ บันทึกเลขช่องจริงกับแท็กที่ H3 รับแยกกันตาม [SOP Analysis](references/sop-analysis.md) ตรวจพรอมป์ต์ ความยาว จำนวนเฟรม ขนาด fps และทางออกเสียง H3 เมื่อบรีฟต้องใช้ ส่งแผนการจับคู่ไฟล์ ค่า และสถานะรายช็อต ใช้ **รอคำสั่ง Gen** เมื่อพร้อมเริ่มช็อตแรกและยังไม่มีคำสั่ง
5. **เรนเดอร์และตรวจช็อตทดสอบ** เมื่อได้คำสั่ง Gen ชัดเจน ให้ส่งหนึ่งช็อตต่อการรัน สำหรับหลายช็อตให้ตรวจและส่งช็อตแรกให้ผู้ใช้อนุมัติก่อนรันที่เหลือ สำหรับช็อตเดียวให้ตรวจแล้วไปขั้น 6 ใช้ ComfyUI Local MCP เพื่อส่งและตรวจคิวหรือประวัติเมื่อเครื่องมือมี ตรวจผลจากไฟล์จริงตาม SOP
6. **ตัดต่อ ตรวจ และส่งออก** ประกอบภาพตามเวลาที่ตกลง ตรวจส่วนเกินจากไฟล์จริงก่อนตัด มิกซ์เสียงพูดต้นฉบับกับแทร็ก H3 ที่ตรวจแล้ว ก่อนส่งมอบให้ยืนยันข้อมูลไฟล์ เช่น ระยะเวลา ความละเอียด และ fps แยกจากการตรวจภาพและเสียงจริง ตรวจภาพด้วยเฟรมจากวิดีโอและตรวจเสียงด้วยการฟังแทร็ก หากทำไม่ได้ อย่าอ้างว่าตรวจแล้ว ให้ระบุข้อจำกัดและส่วนที่ยังไม่ได้ตรวจอย่างชัดเจน ส่งวิดีโอหนึ่งไฟล์ตามบรีฟพร้อมสรุปผลดูและฟัง

การเตรียม storyboard หรือ prompt ให้รายงานตามขอบเขตที่ผู้ใช้ขอ คำสั่ง Gen ที่มาพร้อมอนุมัติชุดแรกเดินหน้าขั้น 3 และ 4 ก่อนส่งช็อตแรก กราฟต้นแบบใช้สำหรับอ้างอิงและทำสำเนา ดาวน์โหลดโมเดลเมื่อผู้ใช้ขอ

สำหรับงาน SOP Analysis อย่างเดียว ให้ส่งสถานะรายช็อต หลักฐาน สิ่งที่ขาด และขั้นถัดไปจาก [แบบบันทึก SOP](references/sop-analysis.md) รายงานว่าเรนเดอร์เสร็จเมื่อผลจาก ComfyUI และไฟล์ผลลัพธ์ยืนยันแล้ว
